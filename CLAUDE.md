# Project Name: SecuRDP

A single Windows executable (`securdp.exe`) that is an SSH-gated Remote Desktop gateway: the **service** on a server/hub PC authenticates with password + TOTP (Google Authenticator) and then only forwards to approved RDP targets; the **client** (same exe, plus an Android app) opens the SSH tunnel and launches Remote Desktop through it. User-facing docs: `README.md`.

## 🛠️ Build & Run Commands
*   **Install Dependencies:** `go mod download` (Go 1.26 — `go.mod` pins `toolchain go1.26.10`; if an older Go is installed set `GOTOOLCHAIN=go1.26.10`). Android: Gradle wrapper fetches everything; needs Android SDK (platform 35) and **JDK 21** (`$env:JAVA_HOME="C:\Program Files\Eclipse Adoptium\jdk-21.0.9.10-hotspot"`).
*   **Run Development Server:** `go run . gui` (native WebView2 window) or `go run . gui --no-open` (prints a tokenised `http://127.0.0.1:<port>/?t=…` URL for a browser). Server-side UI needs an elevated process. `go run . serve` runs the gate in the console (admin; uses the real `C:\ProgramData\SecuRDP` config — see Rules).
*   **Build Project:** build the Android release APK first (it gets bundled into the exe), then `.\build.ps1` → bundles it, runs `go run ./tools/mkres` (icon/manifest/version → `rsrc_windows_amd64.syso`), `go test ./...`, then `go build -trimpath -ldflags "-s -w" -o securdp.exe .`. Android: `cd android; .\gradlew.bat assembleRelease` → `android\app\build\outputs\apk\release\app-release.apk` (copied to `SecuRDP.apk`).
*   **Run Tests:** `go test ./...`. Android: `cd android; .\gradlew.bat testDebugUnitTest` (live tests auto-skip if no gate). Full Android e2e: start a throwaway two-PC hub with `SECURDP_SERVE_ADDR=127.0.0.1:38999 go test ./internal/server -run TestServeForExternalClient` (users `probe.user`/`probe.two`/`probe.three`, `probe.four` may pair app links, shared folders `media`/`drop`, web page `status`, password `Test-passphrase-123`, TOTP secret `JBSWY3DPEHPK3PXP`), then add `-Dsecurdp.e2e.port=38999`.

## 📂 Architecture & Key Paths
*   **Entry Point:** `main.go` — dispatches `gui` (default) / `tray` / `connect` / `install` / `uninstall` / `serve` / `status` / `version`; runs as the Windows service when started by the SCM.
*   **Source Code:** `internal/` (Go), `android/app/src/main/java/app/securdp/` (Kotlin).
*   **Components/Modules:**
    *   `internal/server` — SSH gate: keyboard-interactive auth (password + TOTP), IP banning, hub routing (`user+computer` login suffix, `list.securdp` computer list, named direct-tcpip destinations checked against the user's allow-list), tunnel grace timer, Wake-on-LAN.
    *   `internal/client` — tunnel client (`Connect` → `Computers` → `Listen`), `.rdp` file generation, CLI connect.
    *   `internal/gui` — loopback HTTP API (token + Host check) + embedded web UI in `internal/gui/web/` (vanilla JS/CSS, CSP `'self'`), shown via go-webview2.
    *   `internal/service` — Windows service install/update/migration, tray scheduled task, installed-version check.
    *   `internal/tray` — Win32 notification-area icon; window "show" signalling via a named event.
    *   `internal/config` — server/client JSON config, DPAPI secret protection, folder ACLs, computers/roles model.
    *   `internal/auth` (Argon2id, TOTP, limiter), `internal/ddns` (DuckDNS updater), `internal/netinfo` (public IP), `internal/winutil` (firewall, RDP registry, elevation), `internal/logx`, `internal/version` (**single version source**).
    *   `tools/mkres` — draws the icon in code; writes the `.syso`, web `icon.png` and Android launcher icons.
    *   Android: `Tunnel.kt` (JSch + Bouncy Castle, pure JVM, unit-testable), `TunnelService.kt` (foreground service + state), `MainActivity.kt` (Compose UI), `Profiles.kt`.
*   **Configuration Files:** `go.mod`; `android/app/build.gradle.kts` (`versionCode`/`versionName`); runtime: `C:\ProgramData\SecuRDP\server.json` (+ `hostkey`, `securdp.log`, `ddns-status.json`; SYSTEM/Admins only), `%APPDATA%\SecuRDP\client.json`; secrets: `android/keystore.properties` + `android/securdp-release.jks` (git-ignored).

## 🎨 Code Style & Tech Stack
*   **Stack:** Go 1.26 (golang.org/x/crypto/ssh, x/sys/windows, go-webview2, go-qrcode), Windows 10/11 only; vanilla HTML/CSS/JS UI; Android Kotlin 2.0 + Jetpack Compose (Material 3), AGP 8.13, minSdk 26 / target 35, JSch (mwiede) + Bouncy Castle.
*   **Formatting:** `gofmt`; Kotlin official style. Match the surrounding code: short doc comments explaining *why*, no frameworks in the web UI, no external CDNs (CSP blocks them). Prefer the standard library; ask before adding dependencies.
*   **Rules:**
    *   Never edit generated/build output: `securdp.exe`, `*.apk`, `android/app/build/`, `android/.gradle/`. `rsrc_windows_amd64.syso` and Android `ic_launcher_foreground.png` files are generated by `tools/mkres` — change `tools/mkres` instead.
    *   Never commit or print the signing key or its passwords (`*.jks`, `keystore.properties`). Release APKs must keep using that key or installed apps can't update.
    *   **Don't touch the live install** without the user's explicit OK: don't write `C:\ProgramData\SecuRDP`, restart/install/uninstall the `SecuRDP` service, or change firewall rules — the user may be connected remotely through it. Tests use a temp `ProgramData` with `config.LockServerDir = false`, or the in-process test gates.
    *   Bump the version in `internal/version/version.go` (Windows) and `versionCode`/`versionName` (Android) for each release.
    *   Keep the security model: the gate only ever forwards to configured targets; new capabilities are opt-in, per-user, allow-listed and logged.
    *   Commits end with the Co-Authored-By trailer; run `go test ./...` (and Android unit tests when touched) before committing.

## 📝 Ongoing Migration Context & Status
*   **Current Goal:** **v1.10.0** built (Windows + Android): **Local login at home**: per-user opt-in `User.HomeLogin`; `config.Device.Home` keys are paired over `pair.securdp` (`trust`/`untrust`, list `h` lines) from password+code sessions only (home sessions are refused pairing). `keyLogin` → `homeLogin` accepts them only when the source IP is in the hub's own private subnets (`Server.homeNets`, default `localSubnets()`), giving a normal session (computer via `+suffix`). The hub info adds an `L` line. Windows: `internal/gui/home.go` (ed25519 key, DPAPI user scope `ProtectUserSecret`, `Profile.HomeKey/HomeDevice/HomeHost`, `client.ConnectHome`, Local button). Android: `Profile.homeKeyAlias/homeDevice/homeHost`, `Tunnel.connectHome`, `TrustHomeDialog`, Local button. Also: window sizes scale with display DPI (`internal/gui/windowsize.go`), and the web window has a right-click menu (1.9.1). Before that, v1.9.0 added the hub hands out the **Android app** too. `build.ps1` copies the release APK + versionCode/versionName (from `output-metadata.json`) into `internal/apk/bundle/` (git-ignored, go:embed). The hub info adds `P\tcode\tname`, `apk.securdp` serves it (same reply format as `update.securdp`), and Android downloads it (`Tunnel.downloadApk`) and installs via PackageInstaller (`ApkUpdate.kt`, `InstallResultReceiver`). Build Android first, then `build.ps1`. Before that, v1.8.0 added **Windows update from the hub**: hub info adds a `V	version` line; `update.securdp` serves the hub's own exe (`ok	size	sha256	version` + bytes, `internal/server/update.go`); the GUI banner downloads, checks the hash, test-runs `version`, renames the running exe to `.old`, swaps the new one in and relaunches with `gui --wait-pid` (`internal/gui/update.go`). The installed copy or a read-only folder falls back to Downloads. Before that, v1.7.0 (Windows + Android) added **App links**: per-user opt-in (`User.AppLinks`), devices paired from a password+code session over `pair.securdp` (`pair`/`unpair`/`list` lines) store an ECDSA P-256/Ed25519 public key in `User.Devices`. A key login (`PublicKeyCallback` → `keyLogin`) may only open `svc.<its service>` (`linkChannel`), has its own session cap, and unknown keys don't count toward bans. The hub info adds an `A	1` line. Android: Keystore key (`DeviceKey.kt`), lazy on-demand forwarder (`AppLink.kt`), `LinkService` foreground service + boot receiver, and UI in `LinkScreens.kt`. First user: the AI Pet app (hub page `127.0.0.1:11435`, phone port 11435). v1.6 added Open in browser and Android WebView fixes; v1.5 added Files and Home web pages. Deployed on the user's hub/phone: still 1.4.1 hub on the always-on Plex server (Windows 10 ESU, hub mode, computers `this-pc`, `desktop`, `laptop`) unless updated since. Files use SecuRDP's own protocol over SSH channels (`internal/files`), pseudo destinations `hub.securdp`, `files.securdp`, `hold.securdp`, `pair.securdp`, `svc.<name>`. Path containment uses GetFinalPathNameByHandle (Go's EvalSymlinks doesn't follow junctions); keep that. Small backlog: accept bare 12-hex MAC addresses; picker "wake and wait until online"; laptop still has an old 1.2.1 service installed that the user plans to uninstall.
*   **Active Constraints:** Windows 10/11 paths and APIs (DPAPI, SCM, netsh, WebView2); one exe for every role (client / server / hub). Keep wire compatibility with deployed clients and hubs: `user+computer` logins, `list.securdp` channel (`name online default` lines; new clients try `hub.securdp` first and fall back), destination `127.0.0.1` = login's computer, keyboard-interactive prompts containing "Password" and "Authenticator code". Keep `server.json` / `client.json` backward compatible (new fields optional, zero value = old behaviour). Existing host key / fingerprint and Android signing key must be preserved. The project folder is on a network share (`W:`), so a running `securdp.exe` locks the file — build to a temp name and swap if needed.
